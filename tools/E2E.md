# Сквозная проверка перед выпуском

Два вида проверки, и они не заменяют друг друга.

**Автотесты** (`app/src/androidTest`) — миграции базы и главный путь по экранам. Быстро, повторяемо, запускается одной командой.

**Ручной прогон** — всё, что живёт за пределами приложения: уведомления, будильники, тишина, барьер поверх чужих приложений, виджет в лаунчере. Робот их не проверит: система не даёт подделывать свои события (грабли №11, №16, №19), а вывод команды при этом бодро рапортует об успехе.

## Автотесты

```powershell
$env:JAVA_HOME = "C:\Users\Tornado\Tools\jdk21"
cd C:\Users\Tornado\Projects\Sprout
.\gradlew.bat testDebugUnitTest          # расчёт и формулировки, без устройства
.\gradlew.bat connectedDebugAndroidTest  # миграции и сквозной путь, на эмуляторе
```

> ⚠️ **`connectedDebugAndroidTest` сносит приложение с устройства вместе с базой.** Запускать только на эмуляторе и только когда телефон **не** подключён — иначе настоящие задачи, серия и рост исчезнут без спроса. Проверить, что подключено: `adb devices`. Если подключены оба, выбрать устройство: `$env:ANDROID_SERIAL = "emulator-5554"`.

Что покрыто:

| Тест | Что доказывает |
|---|---|
| `MigrationTest` | База версии 4 с задачей, событием, сессией и садом открывается сегодняшним Room без потерь. Room при открытии сверяет схему сам: забытая колонка не даст базе открыться вовсе |
| `MainFlowTest` | Задача заводится → становится текущей → за неё садятся → пауза и возвращение → завершение. Проверка и по экрану, и по базе: экран может показать правдоподобное, ничего не записав |

## Ручной прогон

Проходится дважды: на **чистой установке** (путь нового человека) и на **живой базе** (то, что видит человек с историей). Пороги наблюдений и экспериментов молчат на бедных данных и говорят на полных — на одной из двух проверок половина экранов просто не появится.

### Чистая установка

- [ ] Первый запуск: «Пока пусто», семя, одна кнопка
- [ ] Диалог про уведомления появляется и разрешение выдаётся. **Без него нет ни отсчёта в шторке, ни сигнала об окончании** — а промолчать он может незаметно
- [ ] Задача заводится с планом «если — то» и напоминанием; кириллица набирается с клавиатуры
- [ ] Будильник встал: `dumpsys alarm | grep -B4 PlanReceiver`
- [ ] Напоминание пришло в срок, в нём обе кнопки. «Начать» заводит сессию, не открывая приложение
- [ ] Сессия: обратный отсчёт в шторке, пауза возвращает звук, «Завершить» ведёт на экран итога
- [ ] Конец сессии по будильнику: сигнал слышно, растение выросло, серия засчиталась
- [ ] «Я» говорит «пока рано», а не показывает выводы из двух случаев
- [ ] Обе темы: `adb shell cmd uimode night yes` / `no`

### Живая база

- [ ] Обновление поверх старой версии не потеряло данные: `pragma user_version`, счётчики задач, событий, сессий, очков
- [ ] «Я»: наблюдения посчитаны и сходятся с прямым запросом к базе
- [ ] Эксперимент: карточка соответствует состоянию (идёт / итог / предложение / тишина)
- [ ] Виджет на домашнем экране показывает текущую задачу и заводит сессию кнопкой
- [ ] Барьер: во время сессии выбранное приложение встречает экраном, обе двери работают
- [ ] «Не беспокоить» включается на сессию и снимается в конце; чужую тишину приложение не трогает
- [ ] Перезагрузка устройства: будильники и идущая сессия на месте

### Чем подкладывать данные

```powershell
.\tools\seed-history.ps1           # месяц правдоподобной истории
.\tools\seed-history.ps1 -Restore  # вернуть как было
.\tools\pull-db.ps1                # снимок базы с устройства
```

Кириллицу и длинный SQL слать файлом (`adb push` + `cat | run-as … sqlite3`), а не строкой: кавычки внутри `adb shell` съедает шелл устройства. Приложение гасить **до** записи и перезапускать **после** — Room не видит правок снаружи.
